# Инструкция по еженедельному обновлению LLM Map

Данный документ описывает процесс еженедельного обновления данных на странице "Трёхуровневая карта LLM-инструментов". Страница спроектирована таким образом, чтобы все данные хранились в одном файле `data.js`, что делает процесс обновления простым и безопасным.

## 1. Что нужно обновлять

Для поддержания актуальности карты необходимо еженедельно проверять и обновлять следующие элементы:

*   **Версии моделей (Уровень 1):** Выход новых версий (например, GPT-5.5, Claude 4.7, Gemini 3.1), изменение контекстного окна, появление новых возможностей (reasoning, multimodal).
*   **Новые инструменты и агенты (Уровень 2):** Появление новых IDE (Cursor, Windsurf), автономных агентов (Devin, Claude Code), браузерных агентов (Manus, Operator).
*   **Платформы и протоколы (Уровень 3):** Рост количества серверов MCP, новые протоколы (A2A, ACP), обновления фреймворков (LangGraph, CrewAI).
*   **Статистика и метрики:** Доли трафика на OpenRouter, результаты бенчмарков (SWE-bench, MMLU), цены на API.
*   **Хронология (Timeline):** Добавление новых значимых событий текущего месяца.

## 2. Где искать обновления

Для сбора актуальной информации рекомендуется использовать следующие источники:

*   **OpenRouter Rankings:** Проверка долей трафика различных моделей (особенно важно для отслеживания китайских моделей).
*   **Официальные блоги компаний:** OpenAI, Anthropic, Google DeepMind, Meta AI, xAI.
*   **GitHub Releases & Trending:** Отслеживание обновлений open-source проектов (n8n, Dify, LangChain, MCP серверов).
*   **Product Hunt:** Поиск новых AI-инструментов и агентных систем.
*   **X (Twitter):** Аккаунты ключевых исследователей и CEO AI-компаний для получения инсайдов и анонсов.
*   **AI Newsletters:** The Rundown AI, TLDR AI, AI Valley.

## 3. Как обновлять данные

Все данные страницы хранятся в файле `data.js`. Для обновления не нужно редактировать HTML или CSS.

1.  Откройте файл `data.js` в любом текстовом редакторе.
2.  Найдите нужный массив данных (например, `levels`, `timeline`, `quizQuestions`).
3.  Внесите изменения в соответствующие поля JSON-объектов.
4.  Сохраните файл.
5.  Откройте `index.html` в браузере для проверки корректности отображения.
6.  Запушьте изменения в ветку `gh-pages` репозитория.

## 4. Формат данных (JSON-структура)

### 4.1. Карточки инструментов (Уровни 1, 2, 3)

Инструменты находятся внутри массива `levels` -> `categories` -> `tools`. Структура карточки инструмента:

```javascript
{
  name: "Название инструмента / Версия",
  url: "https://ссылка-на-официальный-сайт.com",
  description: "Подробное описание инструмента, ключевые обновления, даты релизов.",
  strength: "Главное преимущество или метрика (например, 'SWE-bench 87.6%')",
  features: ["Тег 1", "Тег 2", "Тег 3", "Тег 4"] // До 4 коротких тегов
}
```

### 4.2. Хронология (Timeline)

События находятся в массиве `timeline`. При добавлении нового события добавляйте его в конец массива:

```javascript
{
  date: "Месяц Год (например, Июн 2026)",
  event: "Краткое название события",
  description: "Описание события и его влияния на экосистему"
}
```

### 4.3. Вопросы теста (Quiz)

Вопросы находятся в массиве `quizQuestions`. Структура вопроса:

```javascript
{
  id: 11, // Уникальный номер
  question: "Текст вопроса?",
  options: ["Вариант А", "Вариант Б", "Вариант В"],
  correctIndex: 1, // Индекс правильного ответа (начиная с 0)
  explanation: "Подробное объяснение правильного ответа.",
  level: 2 // К какому уровню относится вопрос
}
```

## 5. Проверка после обновления

После внесения изменений в `data.js` обязательно проверьте:
*   Открывается ли страница без ошибок в консоли браузера.
*   Корректно ли отображаются новые карточки инструментов (особенно теги `features`).
*   Работают ли ссылки на официальные сайты.
*   Правильно ли отображается новое событие в хронологии.
*   Работает ли тест с новыми вопросами.

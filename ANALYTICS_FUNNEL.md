# Образовательная воронка Verkhovskiy.ai → EKEN

## Главная цель

Доля целевых посетителей, которые переходят из полезного контента Verkhovskiy.ai в EKEN.

`EKEN handoff rate = eken_route_handoff / целевые посетители`

## События

| Событие | Этап | Что означает |
|---|---|---|
| `content_engaged_60s` | Ценность | Пользователь провёл на продукте не менее 60 секунд |
| `return_visit_7d` | Удержание | Пользователь вернулся через 1–7 дней |
| `education_interest` | Намерение | Клик по образовательному продукту, программе или курсу |
| `eken_cta_click` | Конверсия | Клик по CTA EKEN или внешней ссылке EKEN |
| `eken_route_handoff` | Основная конверсия | Передача сформированного маршрута в интеграцию EKEN |

События отправляются одновременно в Umami и Яндекс.Метрику. Для обычных ссылок EKEN автоматически добавляются UTM:

- `utm_source=verkhovskiy.ai`
- `utm_medium=referral`
- `utm_campaign=education_funnel`
- `utm_content=<исходный раздел>`

## Недельный scorecard

1. Целевые посетители без аномального трафика.
2. `return_visit_7d / целевые посетители`.
3. `education_interest / целевые посетители`.
4. `eken_cta_click / education_interest`.
5. `eken_route_handoff / целевые посетители` — основной KPI.

## Цели Яндекс.Метрики

Создать JavaScript-события с идентификаторами, полностью совпадающими с именами событий выше. Основной целью назначить `eken_route_handoff`, вспомогательными — остальные четыре.

## Guardrails

- Не считать сырые визиты Umami основным бизнес-KPI без фильтра аномальной географии.
- Не оптимизировать клики в EKEN отдельно от возвратов и содержательного вовлечения.
- Не складывать посетителей разных систем: использовать каждую систему в её собственном временном ряду.

# Техническое задание: устранение разрывов пути Verkhovskiy.ai → EkenLab

Статус: Ready for estimation  
Дата: 2026-08-21  
Основание: аудит тайного покупателя по сценариям главной страницы, карты позиций, карты моделей, новостей, инсайтов, поиска, режима руководителя, PDF и передачи в EkenLab.

## 1. Цель релиза

Сделать путь от аналитического сигнала на Verkhovskiy.ai до проверяемого действия непрерывным и понятным:

`сигнал → контекст → решение/позиция → preview брифа → авторизация → нужный маршрут EkenLab`.

Пользователь до авторизации должен понимать, что будет создано, сколько это займёт и какой результат он получит. После авторизации должен открываться именно выбранный сценарий, а не старый несвязанный черновик.

## 2. Продуктовый результат

### Основной результат

Доля кликов по action CTA, завершившихся открытием корректного маршрута EkenLab, должна составлять не менее 95% среди технически успешных сессий.

### Дополнительные результаты

- Пользователь может получить preview результата без регистрации.
- Ошибка EkenLab не оставляет пользователя на технической странице без альтернативы.
- Режим «Руководитель» становится самостоятельным executive-продуктом, а не косметическим переключателем.
- Поиск объясняет область действия, поддерживает воспроизводимые URL и корректное пустое состояние.
- PDF имеет видимый жизненный цикл: подготовка, загрузка, успех или ошибка.
- Новостные и аналитические выводы можно проверить по источникам.

## 3. Пользователи и ключевые задачи

### Новый посетитель из поиска

Хочет за 5–10 минут понять, что изменилось в AI и что ему с этим делать.

### Руководитель / CAIO

Хочет получить короткий список решений, рисков, ответственных и сроков, сохранить его в PDF и передать коллегам.

### Эксперт

Хочет проверить доказательную базу, отфильтровать события и перейти к конкретному рабочему или образовательному маршруту.

### Пользователь EkenLab

Хочет продолжить выбранный на Verkhovskiy.ai сценарий без потери контекста и без подмены его старым черновиком.

## 4. Объём релиза

### Входит

1. Надёжная передача контекста Verkhovskiy.ai → EkenLab.
2. Preview action brief/decision brief до авторизации.
3. Обработка существующего несвязанного черновика EkenLab.
4. Диагностика и исправление action CTA карты моделей.
5. Fallback при недоступности EkenLab.
6. Переработка режима «Руководитель».
7. Обратная связь и проверяемое завершение PDF-экспорта.
8. Поиск: область, URL-состояние, пустой результат.
9. Источники новостей и инсайтов.
10. Аналитика продуктовой воронки и автотесты.

### Не входит

- Полный редизайн визуального языка сайта.
- Переписывание генератора отчётов или пайплайна n8n.
- Новый LMS или замена интервью AI-наставника.
- Полный accessibility-аудит всех страниц; в релиз входят только требования к изменяемым компонентам.
- Мобильный редизайн карты СРТ.

## 5. P0 — непрерывная передача контекста в EkenLab

### 5.1. Проблема

В ходе аудита наблюдались три исхода одного класса CTA:

- `ERR_CONNECTION_CLOSED`;
- переход на страницу авторизации;
- открытие EkenLab с восстановлением старого несвязанного брифа.

Пользователь не может предсказать результат клика и не видит передаваемый контекст до ухода с сайта.

### 5.2. Требуемый пользовательский сценарий

1. Пользователь нажимает любой CTA «К действию», «Проверить на своём материале» или «Начать освоение».
2. На Verkhovskiy.ai открывается preview-модалка.
3. Preview показывает:
   - источник: событие, инсайт, тренд, модель или позиция;
   - выбранную роль/режим;
   - цель;
   - ожидаемый артефакт;
   - адресата результата;
   - критерий приёмки;
   - оценку времени;
   - какие данные будут переданы EkenLab.
4. Пользователь нажимает «Продолжить в EkenLab».
5. Если EkenLab требует авторизацию, pending handoff сохраняется на сервере или в подписанном краткоживущем токене.
6. После авторизации EkenLab восстанавливает pending handoff.
7. Если существует другой активный черновик, показывается выбор:
   - «Создать новый маршрут по выбранному сигналу» — выбран по умолчанию;
   - «Продолжить существующий черновик».
8. После выбора открывается правильный маршрут с видимым источником Verkhovskiy.ai.

### 5.3. Контракт handoff

Использовать версионированный payload. Минимальная схема:

```ts
type VerkhovskiyHandoffV2 = {
  schemaVersion: "2.0";
  routeId: string;
  scenarioId: string;
  source: {
    surface: "hero" | "event" | "insight" | "trend" | "model" | "position";
    sourceId: string;
    title: string;
    url: string;
    reportDate: string;
  };
  audience: {
    viewMode: "expert" | "executive";
    role?: string;
    locale: "ru" | "en";
  };
  brief: {
    objective: string;
    expectedArtifact: string;
    recipient: string;
    acceptanceCriterion: string;
    estimatedMinutes: number;
    evidence: string[];
  };
  createdAt: string;
  expiresAt: string;
};
```

Требования к контракту:

- `routeId` уникален для пользовательского запуска и идемпотентен при повторной загрузке.
- `scenarioId + source.sourceId` однозначно определяют выбранный CTA.
- Payload валидируется через Zod до открытия EkenLab.
- Payload нельзя молча заменять данными существующего черновика.
- Персональные данные не передаются в URL.
- Предпочтительный вариант — `POST /api/integrations/verkhovskiy/handoffs` с возвратом короткоживущего `handoffToken`.
- Если серверный endpoint пока невозможен, разрешён подписанный токен со сроком жизни не более 30 минут и ограничением размера; обычный открытый JSON в query string не использовать.

### 5.4. Состояния preview CTA

- `idle` — CTA доступен.
- `preview` — пользователь видит итоговый бриф до передачи.
- `creating` — «Готовим переход…», CTA заблокирован от повторного клика.
- `redirecting` — «Открываем EkenLab…».
- `failed-retryable` — сообщение и кнопка «Повторить».
- `failed-service` — сообщение и fallback «Скопировать бриф» / «Открыть внутренний маршрут».

### 5.5. Fallback

Если EkenLab недоступен, пользователь остаётся на Verkhovskiy.ai и может:

- скопировать полный бриф;
- скачать его в `.md`;
- перейти во внутренний шестишаговый маршрут позиции, если он существует;
- повторить подключение.

Техническая ошибка не должна заменять страницу Verkhovskiy.ai.

### 5.6. Критерии приёмки

1. Given пользователь открыл CTA инсайта A, when он авторизовался в EkenLab, then открывается маршрут инсайта A.
2. Given в EkenLab существует черновик B, when приходит handoff A, then система показывает явный выбор и не заменяет A на B автоматически.
3. Given EkenLab недоступен или запрос дольше 8 секунд, then пользователь видит fallback без потери preview.
4. Given CTA нажат дважды, then создаётся один маршрут с одним `routeId`.
5. Given payload не прошёл валидацию, then переход блокируется, ошибка логируется без персональных данных.
6. После авторизации `routeId`, `scenarioId`, `sourceId`, objective и expectedArtifact совпадают с preview.

## 6. P0 — исправление CTA карты моделей

### 6.1. Проблема

«Проверить на своём материале · 20 мин» не меняет URL, состояние или содержимое и не показывает ошибку.

### 6.2. Требования

- Все CTA модели используют единый компонент `EkenRouteAction` и тот же handoff V2.
- У каждой карточки модели должен быть стабильный `sourceId`.
- Перед переходом показывается preview с моделью, тестовым заданием, ожидаемым результатом и временем.
- Если для карточки нет опубликованного сценария, CTA скрывается или заменяется на disabled-состояние «Маршрут готовится»; кликабельный no-op запрещён.
- Карточка показывает дату проверки данных и ссылку «Как рассчитан рейтинг».

### 6.3. Критерии приёмки

1. Для каждой видимой карточки CTA либо открывает preview, либо явно недоступен с причиной.
2. Автотест проходит по всем опубликованным model scenario IDs и проверяет наличие реестра маршрута.
3. После фильтра роли CTA остаётся связан с правильной моделью.
4. Ни один клик не завершается без визуального изменения за 300 мс.

## 7. P1 — режим «Руководитель»

### 7.1. Продуктовое решение

Режим должен отвечать не на вопрос «что произошло?», а на вопрос «что решить сегодня?». Переключатель меняет структуру и приоритеты, а не только объяснения отдельных карточек.

### 7.2. Первый экран executive-режима

Показывать не более:

- 3 решения;
- 3 риска;
- 3 действия.

Каждое действие содержит:

- заголовок;
- основание/сигнал;
- рекомендованное решение;
- владельца;
- срок;
- критерий результата;
- CTA «Собрать decision brief».

Дополнительные разделы сворачиваются под «Показать аналитику».

### 7.3. Поведение

- Режим хранится в `view=executive|expert` в URL и синхронизируется с localStorage.
- URL имеет приоритет над localStorage.
- PDF учитывает выбранный режим.
- Поиск в executive-режиме ищет по решениям, рискам и действиям; исходные события доступны как доказательства.

### 7.4. Критерии приёмки

1. При загрузке `?view=executive` открывается executive-режим.
2. На первом экране не более девяти управленческих карточек суммарно.
3. У каждого действия есть владелец, срок и критерий результата.
4. Переключение режима не вызывает полный reload.
5. Возврат назад восстанавливает предыдущий режим.

## 8. P1 — PDF-экспорт

### 8.1. Требования UI

- После клика сразу показать spinner и текст `Готовим PDF…`.
- Кнопка блокируется от повторного запуска.
- При успехе показать toast `PDF скачан` с именем файла.
- При ошибке показать toast с кнопкой `Повторить`.
- Если браузер заблокировал загрузку, показать прямую ссылку `Скачать PDF`.
- Имя файла: `verkhovskiy-ai-{viewMode}-{locale}-{reportDate}.pdf`.

### 8.2. Требования содержимого

- Executive PDF: решения, риски, действия, источники, дата и критерии результатов.
- Expert PDF: текущий полный аналитический отчёт.
- В PDF фиксируются применённые фильтры и время генерации.
- Пустые или ещё загружаемые секции не должны попадать в документ как завершённые данные.

### 8.3. Критерии приёмки

1. В течение 100 мс после клика виден статус генерации.
2. При успешном `doc.save()` показывается успех.
3. Искусственно вызванная ошибка генератора показывает retry без alert-блокировки интерфейса.
4. PDF открывается, содержит кириллицу и имеет ненулевой размер.
5. Executive и Expert PDF различаются содержанием.

## 9. P1 — поиск и фильтры

### 9.1. Область поиска

Добавить selector области:

- `События и тренды` — default;
- `Инсайты`;
- `Модели`;
- `Весь сайт`.

Если поиск остаётся локальным только для дашборда, label должен прямо говорить `Поиск по событиям и трендам`.

### 9.2. URL-состояние

Синхронизировать:

```text
?q=агенты&levels=6,8&scope=events&view=executive&role=manager
```

Требования:

- обновление через `history.replaceState` во время ввода;
- debounce 200–300 мс;
- back/forward восстанавливают состояние;
- неизвестные параметры игнорируются безопасно;
- после `Сбросить` параметры удаляются.

### 9.3. Пустое состояние

Показывать:

- `По запросу «…» ничего не найдено`;
- активные уровни и область;
- `Снять уровни`;
- `Искать по всему сайту`;
- до трёх связанных тем или последних событий.

### 9.4. Критерии приёмки

1. Запрос `агенты + уровень 6` восстанавливается после reload.
2. Share URL открывает идентичный результат в новой сессии.
3. При нуле результатов виден отдельный empty-state, а не только `0 всего`.
4. Пользователь понимает область поиска до ввода запроса.
5. Число результатов соответствует видимым карточкам.

## 10. P1 — доверие к данным: новости и инсайты

### 10.1. Новость

В раскрытой карточке показывать:

- источник и прямую ссылку;
- дату и время публикации;
- дату анализа;
- отдельные блоки `Факт` и `Почему это важно`;
- связанные события/инсайты;
- CTA `Добавить к decision brief`.

### 10.2. Инсайт

- Каждый пункт доказательной базы кликабелен.
- Отдельно показываются `Факты`, `Интерпретация`, `Рекомендация`.
- Если ссылка недоступна, пункт помечается как непроверенный и не выглядит кликабельным.
- Рядом с прогнозами, зарплатами и оценками уверенности показываются дата и методика.

### 10.3. Критерии приёмки

1. У каждой опубликованной новости есть хотя бы один валидный source URL.
2. Внешние ссылки открываются в новой вкладке с `rel="noopener noreferrer"`.
3. Автоматическая проверка выявляет отсутствующие или невалидные URL до сборки.
4. Пользователь визуально отличает факт от интерпретации.

## 11. P2 — первый экран и терминология

### Требования

- Добавить короткое обещание: `Ежедневно превращаем AI-сигналы в решения и первые действия`.
- Рядом с основным CTA показать `Без регистрации · preview за 1 минуту · полный brief за 30 минут`.
- Объяснить СРТ одной фразой и одним примером до первого использования уровней.
- Добавить guided path: `Сигнал → Позиция/решение → Самооценка → Бриф`.
- Плавающая подписка не должна перекрывать основной CTA, формы, footer или содержимое на ширине от 320 px.

Использовать единые события с обязательными параметрами `routeId`, `scenarioId`, `sourceId`, `surface`, `viewMode`, `locale`:

```text
action_cta_clicked
handoff_preview_opened
handoff_confirmed
handoff_created
handoff_redirect_started
eken_auth_required
eken_route_opened
eken_draft_conflict_shown

```

Не отправлять в аналитику email, имя, текст пользовательского брифа и другие персональные данные.

### Воронка

1. CTA clicked.
2. Preview opened.
3. Handoff confirmed.
4. Auth completed, если нужна.
5. Correct route opened.
6. First action started.

## 13. Нефункциональные требования

### Надёжность

- Таймаут handoff API: 8 секунд.
- Retry: один автоматический запрос только для сетевой ошибки до создания handoff.
- После получения `routeId` повторный POST идемпотентен.
- Ошибка EkenLab не должна уводить текущую вкладку с Verkhovskiy.ai; открывать новую вкладку только после успешного создания handoff.

### Производительность

- Preview открывается до 200 мс после клика.
- Фильтрация локальных данных — до 100 мс на типовом наборе.
- PDF показывает начальное состояние до 100 мс, полная генерация — целевой p95 до 8 секунд.

### Доступность

- Все новые диалоги имеют `role="dialog"`, заголовок и focus trap.
- После закрытия focus возвращается на исходный CTA.
- Все состояния доступны без мыши.
- Loading/success/error объявляются через `aria-live`.
- Контраст текста и интерактивных состояний соответствует WCAG AA.
- Touch target не меньше 44×44 px.

### Безопасность и приватность

- Не помещать персональные данные и полный brief в query string.
- Токен handoff одноразовый или краткоживущий.
- Логи не содержат пароль, email, содержимое приватного черновика.
- Не сохранять заполненные поля авторизации в screenshots, telemetry или error reports.

Репозиторий: `ai-integrated-report-eken-entrypoints`.

- Идемпотентное создание маршрута по `routeId`.

## 15. Тестирование

### Unit

- Валидация handoff V2.
- Сериализация фильтров в URL.
- Приоритет URL над localStorage.
- Выбор executive/expert PDF.
- Маппинг каждого CTA на scenario/source ID.

### Integration

- CTA → preview → POST handoff → redirect URL.
- Auth required → login callback → correct route.
- Existing draft conflict → both user choices.
- Network timeout → fallback.
- Model card without registry entry → disabled state.

### E2E

1. Новый пользователь: главный CTA → preview → login → правильный decision brief.
2. Авторизованный пользователь со старым черновиком → конфликт → новый маршрут.

## 17. Definition of Done

Задача считается выполненной, если:

- все критерии приёмки P0 пройдены на staging;
- все опубликованные CTA имеют рабочий сценарий или явное disabled-состояние;
- E2E подтверждает сохранение контекста через авторизацию;
- нет P0/P1 ошибок консоли в проверяемых сценариях;
- добавлены аналитические события без персональных данных;
- обновлена документация контракта handoff;
- проведена ручная проверка RU/EN и трёх viewport;
- продуктовый владелец подтвердил четыре контрольных сценария: главный CTA, инсайт, модель, позиция.

## 18. Открытые решения до разработки

1. Где хранится pending handoff: EkenLab backend или общий integration service.
2. Нужен ли пользователю список сохранённых handoff после авторизации.
3. PDF должен скачиваться напрямую или сначала открываться в preview.
4. Поиск «Весь сайт» выполняется по клиентскому индексу или отдельному API.
5. Какие поля считаются обязательными для источника новости и доказательства инсайта.

Рекомендация: начать с server-side pending handoff в EkenLab, прямой загрузки PDF и локального индексированного поиска по данным текущего отчёта. Это минимизирует риск потери контекста и не требует нового поискового backend на первом этапе.

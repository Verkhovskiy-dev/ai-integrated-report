# Кнопки с проверяемым результатом

Вызов: `$site-buttons Добавь кнопку <название> в <экран/карточку>, по нажатию <результат>`.
Если скилл ещё не появился в списке текущей сессии, попроси прочитать
`.agents/skills/site-buttons/SKILL.md` в этом checkout и выполнить запрос по нему.

## Установи место и действие

- Прочитай применимые AGENTS.md; проверь remote, ветку, HEAD и status. Этот скилл
  хранится в инженерном репозитории `Verkhovskiy-dev/ai-integrated-report`.
  Не переноси изменения в старую соседнюю копию и не перезаписывай чужую работу.
- Найди поддерживаемый компонент, данные и генератор. Не правь `dist/` или
  опубликованный HTML вместо исходника. Посмотри актуальные package.json и workflow.
- Определи поверхность, подпись RU/EN, условие видимости, действие и наблюдаемый
  успех. Различай переход по ссылке, локальное переключение и запись на сервере.
  Уточняй только неопределённость, существенно меняющую сценарий.
- При создании обычной кнопки не запускай новый сервер или редакторскую систему.
  Для реакций/журнала прочитай [references/reactions.md](references/reactions.md).

## Реализуй сквозной сценарий

- Переиспользуй `client/src/components/ui/button.tsx` и существующие варианты,
  если они подходят. Для действия — семантический button с `type="button"`,
  для навигации — ссылка (при необходимости Button `asChild`). Не вкладывай
  button в ссылку или другую кнопку; не ломай открытие карточки и меню share.
- Обеспечь доступное имя, видимый keyboard focus, Tab/Enter/Space для кнопок,
  `aria-pressed` для выбранного toggle, подпись для иконки. Проверь мобильный
  touch target и перенос длинного русского текста в реальной карточке.
- Для асинхронного действия предусмотрены ожидание, успех, ошибка и повтор.
  Блокируй случайные повторные отправки; показывай «сохранено» только после
  подтверждения сервера. Игнорируй устаревший ответ после смены карточки.
- Клиентский localStorage не является общим журналом редактора. Нужны API,
  постоянное хранилище и закрытое чтение. Секреты не помещай в клиент, URL,
  Git, скриншоты или логи. Не считай CORS заменой авторизации редактора.
- Аналитическое событие клика и подтверждённая бизнес-операция различаются.
  Не передавай личные тексты в аналитику; технические проверки не называй
  откликом аудитории или доказательством роста.

## Проверь и передай

- Из актуального package.json выбери targeted tests и проверку типов; выполни
  сборку по действующему workflow. До/после проверь diff: генерация не должна
  незаметно добавить чужие данные. Не исправляй несвязанные дефекты ради зелёного CI.
- Пройди desktop/mobile сценарий в браузере: клавиатура, обычный клик, быстрый
  повтор, ошибка сети и повторная попытка. Для сохранения проверь reload;
  для переключения — выбор/изменение/снятие. Проверь соседние ссылки и share.
- Для server-backed действия докажи цепочку UI → API → запись → редакторская
  сводка, а не только HTTP 200. Используй изолированный тестовый идентификатор.
  Production-записи и удаление тестовых строк выполняй только в разрешённом
  объёме; удаляй лишь точно установленные собственные записи.
- Укажи файлы, версию кандидата, выполненные проверки и пробелы. Скилл не даёт
  разрешение на push/deploy, оплату инфраструктуры или внешние сообщения.
  Учитывай уже выданное разрешение для конкретного изменения, не спрашивай его
  повторно. После разрешённого деплоя проверь публичную версию и живой сценарий,
  сохрани предыдущий SHA/артефакт для отката. Сбой доступа фиксируй, не обходи.

Готовность: кнопка выполняет заявленное действие; ошибки не маскируются успехом;
проверки соответствуют затронутому поведению. Локальная готовность, выпуск и
продуктовая приёмка — три разных статуса.

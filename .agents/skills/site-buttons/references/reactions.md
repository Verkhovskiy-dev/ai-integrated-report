## Инварианты изменения

- Сохраняй стабильные newsId/contentVersion и семантику текущих реакций.
  Добавляя тип реакции, обнови согласованно UI, клиент, серверную валидацию,
  хранилище/миграцию при необходимости, сводку и тесты. Не ограничивайся OPTIONS.
- Отделяй текущее состояние реакции от журнала операций set/change/remove.
  Снятие реакции не должно выглядеть как ещё один положительный отклик.
- Сохраняй идемпотентность повторной отправки и контроль версии. При конфликте
  другой вкладки не перезаписывай её выбор молча. Не удваивай запись при retry.
- Проверяй неизвестную/устаревшую новость, недоступный API, отсутствие
  localStorage, устаревший ответ после смены карточки и доступ без редакторского
  токена. Редакторский токен остаётся только в защищённой серверной конфигурации.
- Сайт на GitHub Pages не исполняет серверный Node-код. API разворачивается
  отдельно; не считай сборку frontend выпуском backend. Используй существующую
  инфраструктуру, новый ресурс/изменение доступа требуют соответствующих полномочий.
- Для реестра проверь согласованный снимок RU/EN, атомарное обновление и TTL;
  не заменяй свежесть данных доступностью URL. Проверь переживание перезапуска
  сервиса постоянным хранилищем в изолированной среде.
- Сводка должна явно обозначать период/часовой пояс и что именно ранжируется:
  активные реакции, операции или браузерные идентификаторы. Browser ID не равен
  доказанному уникальному человеку, а число реакций без экспозиции — не CTR.

В этой версии `npm run test:reactions` запускает проверки identity, client,
store, registry и API; серверные тесты SQLite требуют совместимого Node runtime.
Сначала сверяй текущий package.json и требования исходников. Проверка типов —
`npm run check`, сборка — `npm run build`; публичный build сверяй с
`.github/workflows/deploy-dashboard.yml`.

Примеры проверки самого скилла (без production-мутаций):

- «Добавь кнопку раскрытия источников» → локальный UI, без нового API.
- «Добавь реакцию “Спорно” с записью редактору» → согласованный контракт всех слоёв.
- «Показывай “Сохранено”, даже если API не отвечает» → честная ошибка/ожидание,
  не ложное подтверждение записи.
